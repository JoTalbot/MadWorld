# Инструкции для AI-агентов MadWorld

> **Главный операционный контракт:** `docs/CHATGPT_AGENT_RULES.md` содержит постоянные правила автономной работы, ожидания результатов, исправлений, Remote Operator, release gates и минимизации ручных действий. При начале работы с репозиторием агент обязан прочитать этот документ вместе с `AGENTS.md`.
>
> **Обязательный живой skill проекта:** `docs/skills/MADWORLD_AGENT_SKILL.md`. Каждый новый агент/работник обязан прочитать и применять его ДО изменения репозитория. Это эволюционирующий слой знаний проекта: любой новый подтверждённый опыт, полезный следующим агентам, должен быть сохранён туда в том же логически связанном батче.

## Обязательный onboarding для каждого нового агента

Перед первой модификацией репозитория каждый новый агент/работник MUST прочитать:

1. `AGENTS.md`
2. `docs/CHATGPT_AGENT_RULES.md`
3. `docs/REMOTE_OPERATOR.md`
4. `.github/remote-operator/QUEUE.md`
5. `docs/skills/MADWORLD_AGENT_SKILL.md`

Агент, который не загрузил skill, **НЕ ГОТОВ К ИЗМЕНЕНИЮ РЕПОЗИТОРИЯ**.

После завершения нетривиальной работы агент обязан проверить, появился ли новый переиспользуемый опыт. Если появился, его нужно добавить в `docs/skills/MADWORLD_AGENT_SKILL.md`, а затем повторить релевантные проверки.

## Формат ответов

При взаимодействии с пользователем AI-агент должен:

- Использовать **маркированные списки** как основной формат ответа.
- Структурировать информацию подзаголовками и короткими пунктами для удобного чтения.
- Использовать эмодзи умеренно, но заметно, для визуального обозначения статусов и типов информации.
- Сохранять техническую точность и не жертвовать содержательностью ради форматирования.

## Автономная работа без остановки

- Если пользователь пишет `+`, «делай всё», «одним батчем», «до конца» или аналогичную команду, выполнить весь текущий логически связанный этап.
- Не останавливаться после первого найденного дефекта.
- Если операция запущена и требуется результат, обязательно дождаться terminal result или timeout.
- Если результат требует правок, автоматически внести их, повторить тесты и проверки и продолжить.
- Цикл: **ANALYZE → IMPLEMENT → TEST → VERIFY → FIX → RE-TEST → REPORT**.
- Если появляется новый подтверждённый опыт, дополнить цикл этапами **LEARN → DOCUMENT** через проектный skill.
- Не запрашивать промежуточное подтверждение, если следующий шаг технически необходим и уже разрешён текущей задачей.
- Остановка допустима только при реальном внешнем/юридическом/owner-блокере или технической невозможности, с явной фиксацией причины.

## GitHub + Remote Operator

- GitHub является source of truth для кода, workflows и документации.
- Перед существенными изменениями проверяй текущую ветку и HEAD.
- Для серверных операций используй **Remote Operator** через каноническую очередь `.github/remote-operator/COMMANDS.txt`.
- Все AI-агенты MadWorld имеют право использовать Remote Operator для выполнения серверных Bash/SSH-операций, необходимых для диагностики, тестирования, деплоя, обслуживания и проверки проекта.
- Агент должен не выполнять SSH-команду самостоятельно вне предусмотренного механизма, а создавать задание в `COMMANDS.txt`, если операция предназначена для Remote Operator.
- Remote Operator намеренно поддерживает произвольные shell-команды без command allowlist.
- Короткие операции выполняй в `sync`, длительные — в `async` с polling и timeout.
- Для server-side queue executor lifecycle: `PENDING -> CLAIMED -> RUNNING -> DONE | FAILED | TIMEOUT | CANCELLED | INTERRUPTED | INVALID`.
- После постановки серверной задачи агент обязан дождаться фактического терминального результата.
- Проверяй `stdout`, `stderr`, `exit_code`, состояние выполнения и доступный result artifact/record.
- Не утверждай, что операция выполнена, если она не подтверждена фактическим результатом.
- Secrets и приватные ключи никогда не записывать в репозиторий, логи, artifacts, issues или отчёты.
- Не делать force push без явного указания.
- После исправления повторять релевантные проверки и тесты.

## Remote Operator command queue

- Канонический файл очереди Bash-команд: `.github/remote-operator/COMMANDS.txt`.
- **Все новые Bash-команды, которые должны быть выполнены Remote Operator, обязательно дописывать в конец `.github/remote-operator/COMMANDS.txt`.**
- Не перезаписывать, не сортировать и не удалять существующие записи.
- Каждой команде назначать уникальный неизменяемый `COMMAND_ID`.
- Новая команда должна иметь `STATUS: PENDING`.
- Агент не должен самостоятельно выполнять такую команду, если задача предназначена для Remote Operator.
- Только исполнитель Remote Operator переводит команду в `CLAIMED`, затем `RUNNING`, а после завершения в терминальное состояние.
- Уже обработанные команды нельзя автоматически выполнять повторно с тем же `COMMAND_ID`.
- Сохранять выполненные команды как audit trail.
- Не помещать в очередь пароли, токены, приватные ключи, cookies или другие секреты.

## Работа одним батчем

Если пользователь пишет `+`, «делай всё», «одним батчем», «до конца» или аналогичную команду, выполнить весь текущий логически связанный этап: анализ → изменения → тесты → проверка → исправления → повторная проверка → фиксация нового опыта в skill → итоговый отчёт.

## Постоянное накопление опыта

`docs/skills/MADWORLD_AGENT_SKILL.md` является **живой памятью проекта для агентов**.

Правила:

- Любой новый агент обязан применять skill.
- Каждый агент обязан дорабатывать skill при появлении нового подтверждённого опыта.
- Уроки должны быть краткими, проверяемыми и пригодными для повторного использования.
- Гипотезы не превращать в обязательные правила без проверки.
- Исправлять устаревшие уроки только на основании новых подтверждённых фактов.
- Репозиторий должен оставаться самодостаточным: следующий агент не должен зависеть от личной истории предыдущего агента или содержимого старого чата.
- Skill, `AGENTS.md` и операционная документация должны оставаться согласованными.
